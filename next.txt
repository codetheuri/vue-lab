

1. Loading states for buttons and tables (preparing for APIs)
Right now everything happens instantly because our data is in local storage, but when we connect a real backend API, loading a table or saving a form takes a moment.
- Update our reusable button component so it can show a loading spinner and disable clicking while an action is running (so someone can't click Save twice).
- Update our reusable table component so it can show a loading spinner inside the table while records are loading.
- Add a short simulated delay (around half a second) when saving a form and when resetting or loading table data so we can see both loading spinners working in the browser.

2. Employee Profile page (/employees/:id) and a 404 Not Found page
Right now all our routes are static URLs. Let's practice dynamic route parameters.
- Build a dedicated Employee Profile page at `/employees/:id` and let users navigate to it from the Employees table and Dashboard.
- Show the employee's full details on that page, and if someone visits an ID in the URL that doesn't exist (like `/employees/999`), show a clean "Employee not found" state with a button back to the directory.
- Also replace the catch-all redirect in the router with a proper 404 Not Found page whenever someone visits a broken URL.

3. Assign company equipment from Products to an Employee
Right now Employees and Products are completely separate. On the new Employee Profile page, let an Admin assign products from our inventory to that employee (for example, assigning a workstation or monitor to them) and list the items they currently hold.
Make sure the inventory math stays accurate in all cases:
- Assigning a product to an employee must reduce that product's available stock by 1 (and out-of-stock products cannot be assigned).
- Unassigning/returning an item from the employee must increase that product's stock back by 1 (and update its stock status badge if needed).
- If an employee is deleted (either single delete or bulk delete) while they still hold company equipment, make sure their assigned items are automatically returned to product stock.

4. Clean up the repeated table logic between Employees and Products
If you compare the script section of the Employees page and the Products page, they repeat almost the exact same code for searching, sorting, pagination, and clearing filters.
- Move that shared table state and logic into a single reusable composable so both pages use it instead of repeating the same code twice.
- Include a short debounce on the search input so filtering waits until the user pauses typing.
