1. Install Pinia and create an Auth Store (src/stores/authStore.js)
Let's move into state management using Pinia stores and add authentication to the app.
- Install Pinia (`npm install pinia`) and register `createPinia()` in `src/main.js`.
- Create `src/stores/authStore.js` using `defineStore('auth', () => { ... })`.
- Store the logged-in `user` in a `ref` (loaded from `localStorage` under `'app_auth_user'` so refreshing the browser keeps you logged in).
- Add computed properties:
  - `isAuthenticated`: returns `true` when `user.value` exists.
  - `isAdmin`: returns `true` when `user.value?.role === 'Admin'`.
  - `userInitials`: returns the 2-letter initials from `user.value?.name`.
- Add actions:
  - `login(email, password)`: check credentials against demo accounts (for example: Admin `admin@company.com` / `admin123` with role `Admin` and name `Alex Morgan`, and Staff `staff@company.com` / `staff123` with role `Viewer` and name `Sarah Jenkins`). If valid, set `user.value`, save to `localStorage`, and return `true`; otherwise return `false`.
  - `logout()`: set `user.value = null` and remove `'app_auth_user'` from `localStorage`.

2. Build the Login Page (src/pages/Login.vue)
- Create `src/pages/Login.vue` with a clean centered login card using `BaseInput` and `BaseButton`.
- Add Email and Password fields with `:error` validation (check for empty fields and show an error message or danger toast if login fails).
- Display the demo Admin and Viewer login credentials at the bottom of the card so anyone testing knows what email and password to use.
- When `authStore.login(...)` succeeds, trigger a welcome toast (`showSuccess`) and navigate to `/` using `useRouter()`.

3. Update App.vue and router/index.js for Login and Route Guards
- In `src/router/index.js`, add a `/login` route pointing to `Login.vue` with `meta: { title: 'Sign In', guestOnly: true }`.
- Add `meta: { requiresAuth: true }` to the `/`, `/employees`, and `/products` routes.
- Add a `router.beforeEach` navigation guard that checks `useAuthStore()`:
  - If the route requires auth and `!authStore.isAuthenticated`, redirect to `/login`.
  - If the user is already logged in and tries to visit `/login`, redirect to `/`.
- Update `src/App.vue` so the `/login` page renders on its own without `<DashboardLayout>` (no sidebar or topbar on the login screen), while authenticated pages still render inside `<DashboardLayout>`.

4. Connect the logged-in user and Logout button in DashboardLayout.vue
- Open `src/layouts/DashboardLayout.vue` and replace the hardcoded `"Alex Morgan"`, `"Administrator"`, and `"AM"` in the topbar with `authStore.user?.name`, `authStore.user?.role`, and `authStore.userInitials`.
- Add a Logout button (`BaseButton` or button with `bi-box-arrow-right`) in the topbar or sidebar footer that calls `authStore.logout()`, shows a toast, and sends the user back to `/login`.

5. Restrict Add, Edit, Delete, and Reset actions by user role
- In `Employees.vue` and `Products.vue`, import `useAuthStore()`.
- If the logged-in user is not an Admin (`!authStore.isAdmin`), hide the Add, Edit, Delete, and Reset Data buttons so a `Viewer` account can only browse, search, filter, quick-view details, and export CSV.
- Also in `Products.vue`, add `'Software'` and `'Hardware'` to `modalCategoryOptions` so editing those existing products selects their category properly.
