1. Fix the status badge in Dashboard.vue and button in Products.vue
- In `Dashboard.vue`, `<BaseBadge>` in the Recent Employees table still uses `:text="emp.status"`. Since `BaseBadge.vue` uses `<slot />`, change it to `<BaseBadge ...>{{ emp.status }}</BaseBadge>` so the status text shows up.
- Also in `Dashboard.vue`, clicking the eye button on a recent employee currently just routes to `/employees`. Change it so clicking the eye icon opens a `BaseModal` showing that employee's details (name, email, department, role, status badge, and join date).
- In `Products.vue`, inside the Add/Edit modal, replace the plain `<button type="submit" class="btn btn-primary btn-sm">` with `<BaseButton>`.

2. Add field error messages to BaseInput.vue
Right now when a form has missing or invalid inputs, we only show a general toast error.
- Add an `error` prop (String, default `''`) to `BaseInput.vue`.
- When `error` is passed, add Bootstrap's `is-invalid` class to the `<input>` element and show `<div v-if="error" class="invalid-feedback">{{ error }}</div>` right under the input.
- In `Employees.vue` and `Products.vue`, validate each field when saving and pass field-specific error messages to `BaseInput` (for example: name is required, email must be valid, department and role are required; for products: name and category are required, price must be greater than 0, and stock must be 0 or more). Make sure old error messages clear when opening or closing the modal.

3. Fix number saving and last-page deletion bugs
- In `Products.vue`, `BaseInput` emits strings, so saving a new or edited product can store `price` and `stock` as strings instead of numbers (which breaks numeric sorting). In `saveProduct`, convert `price` and `stock` using `Number()` before saving.
- In both `Employees.vue` and `Products.vue`, if you are on the last page of the table (e.g. Page 2) and delete the only remaining item on that page, the table stays on Page 2 and shows "No matching records found" even though Page 1 still has items. Add logic so if `currentPage` ends up higher than the total pages after a delete, it automatically moves back to the last available page.

4. Add a Status filter and a Clear Filters button
- In `Employees.vue`, add a second `TableFilters` dropdown next to Department to filter by Status (`All Statuses`, `Active`, `Inactive`).
- In `Products.vue`, add a second `TableFilters` dropdown next to Category to filter by Availability (`All Statuses`, `In Stock`, `Low Stock`, `Out of Stock`).
- In both pages, add a small "Clear Filters" button in the table header that only shows up when a search query, dropdown filter, or column sort is active. Clicking it should reset search, filters, and sorting back to default.

5. Add a "Reset Demo Data" button
Since changes are now saved in `localStorage`, deleting or editing items permanently changes the data until storage is cleared manually.
- In `useEmployees.js` and `useProducts.js`, add a `resetEmployees` and `resetProducts` function that restores the list back to the original `initialEmployees` / `initialProducts` data (make sure to clone the initial array so mutations don't overwrite the original mock array in memory).
- Add a "Reset Data" button on the `Employees.vue` and `Products.vue` pages that restores the default data and triggers an info toast.
