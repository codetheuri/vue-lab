

1. Server-Side Bulk Delete & Single-Record Fetch (`GET /:id` + `bulk-delete`)
- Right now, selecting 5 rows and clicking "Delete Selected" on Employees or Products sends 5 separate `DELETE` requests in a loop. Add single bulk-delete endpoints on `server/index.js` for employees and products (returning `403` for non-Admins, and returning assigned equipment back to stock when bulk-deleting employees) and wire a `bulkRemove(ids)` method through your services and stores.
- Also add `GET /api/employees/:id` and `GET /api/products/:id` endpoints to `server/index.js` and `getById(id)` to your services.

2. Complete the Auth Lifecycle (`/api/auth/me`, Change Password, and Forgot Password)
- Add a `GET /api/auth/me` endpoint on `server/index.js` and call it on app startup when a token exists so the app verifies the saved session against the server and refreshes the user's latest role/name.
- Add a "Change Password" form inside the My Profile modal backed by `POST /api/auth/change-password` (verifying the current password, validating minimum length, and saving the new password to `server/db.json`).
- Add a Forgot Password page (`/forgot-password`) linked from the Login screen so the auth flow is complete for any future project.

3. Shared Form Validation Helpers (`src/utils/validators.js`) & Request Timeout in `api.js`
- Create a shared `src/utils/validators.js` module (`isRequired`, `isEmail`, `minLength`, `isPositiveNumber`, plus a helper that maps `422` server validation errors into a form's `errors` object) and use it in your Login, Employees, and Products forms to remove repeated inline validation code.
- Add request timeout support (`VITE_API_TIMEOUT` using `AbortController`) and a `multipart/form-data` upload helper (`api.upload`) to `src/services/api.js`.
