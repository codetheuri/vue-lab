
1. Fix the Product Availability filter when the Low Stock Threshold changes
Test this in your browser right now:
- Go to Settings and change the Low Stock Alert Threshold from `10` to `25`.
- Now go to the Products page: you will see more products showing the yellow `Low Stock` badge in the table because the badge checks `row.stock < lowStockThreshold`.
- However, now open the "Availability" filter dropdown at the top of the Products table and select `Low Stock` — those products disappear!
Why? Because your table composable filters by the static `item.status` string saved in storage instead of the live status calculated from `lowStockThreshold`. Fix the product store/table filtering so the Availability filter dropdown and CSV export always match the live status badge when the threshold changes.

2. Add Error & Retry State to DataTable and Stores
Right now `DataTable` handles `:loading="loading"`, but in real API mode (`VITE_USE_MOCK_API=false`), if the backend server is offline or returns an error, the request fails and the user just sees an empty table ("No matching records found") with no idea that the network request failed.
- Add an `error` state ref to your employee and product stores inside `try / catch` when fetching records.
- Add an `:error` prop and `@retry` event to `DataTable`: when `error` has a message, display a clean error alert state inside the table with the error message and a "Try Again" button that triggers the store's fetch action again.

3. Build a Working Global Search / Command Palette (`Ctrl+K` / `Cmd+K`) in the Topbar
Add a global search button (`Search... Ctrl+K`) in the top header bar next to the notification bell:
- Pressing `Ctrl+K` (or `Cmd+K`) anywhere in the app — OR clicking the button in the topbar — must open a search modal, and pressing `Ctrl+K` or `Escape` again must close it. (Make sure the keyboard shortcut actually opens the modal when it is closed!)
- Typing in the search box should search across three groups at once:
  1. **Pages** (Dashboard, Employees, Products, Activity Log, Settings — respecting the current user's role permissions)
  2. **Employees** (matching name, email, department, or role)
  3. **Products** (matching product name, SKU, or category)
- Clicking any search result must close the modal AND actually navigate the user to that page or employee profile (`/employees/:id`).

4. Add Workspace Data Backup & Restore to the Settings Page
On the `/settings` page, add a **Data Backup & Restore** card (visible only to Admins):
- **Export Workspace Backup (JSON):** Downloads a single `.json` file containing the current employees, products, activity logs, and system settings with a timestamp.
- **Restore from Backup (JSON):** Lets an Admin upload a previously exported `.json` backup file, validates that it has valid data arrays before overwriting, updates the Pinia stores and `localStorage`, logs the restore action in the activity log, and shows a success toast.
